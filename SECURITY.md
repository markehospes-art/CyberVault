# Security Policy

## Supported versions

This repository is a documentation and learning project. We do not provide a formal software release cycle, but we still appreciate responsible disclosure for issues affecting repository integrity, documentation problems, or unsafe examples.

| Version | Supported |
|--------|-----------|
| main branch | Yes |

## Reporting a vulnerability

If you discover a security-related issue, please report it responsibly.

Please send an email to:
- markehospes@gmail.com

Include:
- a clear description of the issue
- affected file(s) or paths
- steps to reproduce if relevant
- suggested fix or remediation if known

Please do not disclose the issue publicly until it has been reviewed and addressed.

## Responsible disclosure

We ask that reporters:
- avoid exploitation or destructive testing
- avoid accessing data beyond what is needed to confirm the issue
- keep reports focused on the vulnerability itself
- allow reasonable time for a fix before public disclosure

## Scope

This policy covers:
- unsafe or misleading security examples
- vulnerabilities in repository content or scripts
- issues affecting how the repo is used in practice

This policy does not cover:
- general learning questions
- non-security documentation feedback
- ethical hacking practice in unauthorized environments

## Thanks

Thanks for helping keep this project safer and more trustworthy.
